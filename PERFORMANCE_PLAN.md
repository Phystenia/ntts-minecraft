# План оптимизации NTTS

Статус: implemented
Цель: уменьшить количество обращений к `/N/TTS`, задержку ответа и расход памяти без изменения команд и голосового транспорта.

## 1. Базовые метрики

Зафиксировать счётчики HTTP-запросов, cache hit/miss, in-flight deduplication,
пропусков из-за отсутствия слушателей, вытеснений кеша, отказов очереди и
задержки синтеза. Показывать их через `/ntts status` без токена и полного текста.

## 2. Проверка слушателей до синтеза

Перед постановкой задачи в очередь:

1. Для `local` проверить подключение Simple Voice Chat у говорящего.
2. Для `global` оставить только игроков с доступным voice-chat connection.
3. При пустом списке увеличить `skippedNoListeners` и не обращаться к API.
4. Перед воспроизведением проверить соединение повторно.

## 3. Дедупликация параллельных запросов

Добавить `in-flight` таблицу по SHA-256 от нормализованного текста, голоса,
эффекта, формата и sample rate.

- Первый запрос владеет генерацией.
- Одинаковые запросы присоединяются к его результату.
- Один HTTP-вызов обслуживает всех ожидающих получателей.
- Запись удаляется после успеха или ошибки в `finally`.
- Нельзя блокировать единственный worker через `Future.get()`; pending request
  должен хранить playback-consumer'ов.

## 4. Memory-cache с TTL

Сохранить текущий потокобезопасный LRU-кеш PCM, но вынести параметры в конфиг:

```properties
memory_cache_enabled=true
memory_cache_mb=16
cache_ttl_minutes=1440
```

Просроченные записи не выдаются. Лимит размера и TTL должны соблюдаться, а
ошибки кеша не должны останавливать сервер.

## 5. Опциональный disk-cache

По умолчанию выключен:

```properties
disk_cache_enabled=false
disk_cache_directory=config/ntts-cache
disk_cache_mb=256
```

Ключ — SHA-256 без токена и исходного текста. Запись идёт во временный файл с
последующим atomic move; формат, размер, TTL и целостность проверяются при чтении.
Общий размер ограничивается, старые записи вытесняются. Ошибки диска безопасно
откатываются к memory-cache.

## 6. Rate limit и очередь

Сохранить один worker и ограничение очереди. Cache hit не считать HTTP-запросом.
Перед сетевым вызовом повторно проверять состояние провайдера, backoff и квоту.

## 7. Проверка и выпуск

Проверить один HTTP-запрос для одинаковых параллельных фраз, memory hit для
последовательных, новый запрос после TTL, disk-cache после перезапуска,
отсутствие запроса без слушателей, выход игрока во время синтеза, повреждённые
файлы кеша и отображение новых счётчиков в `/ntts status`. Затем прогнать
NeoForge, Fabric и Forge сборки.
