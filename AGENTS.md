# AGENTS.md

## Проект

Это Java-проект Minecraft-мода `ntts-voicechat` на Gradle с multi-loader структурой:

- `common/` — общий код;
- `fabric/` — Fabric-реализация;
- `forge/` — Forge-реализация;
- `versions/` — version-профили Minecraft;
- `build.gradle` и `settings.gradle` — общая конфигурация сборки.

Перед изменениями сначала проверь выбранный профиль через `-PmcVersion`. Не смешивай API, mappings, названия ресурсов и зависимости разных loader'ов.

## Java и целевая NeoForge-версия

- Целевая среда NeoForge: `21.1.248` для Minecraft `1.21.1`.
- Для Minecraft `1.21.1` используй Java `21`.
- Репозиторий содержит Fabric-, Forge- и отдельный `neoforge/` модуль. NeoForge-модуль поддерживается только для профиля `1.21.1`; не используй Forge-код или зависимости как его замену.
- Текущий профиль `1.20.1` использует Java `17`; профиль `1.21.1` — Java `21`. Всегда сверяй `versions/<version>.properties` перед изменением исходников или Gradle-конфигурации.

## Рабочие правила

1. Сначала изучи существующую структуру, профиль версии, mappings и ближайшие тесты.
2. Делай минимальные изменения и сохраняй текущую архитектуру multi-loader.
3. Для новых игровых объектов обновляй Java-код и связанные ресурсы/data-файлы вместе.
4. Регистрацию объектов, события, datagen, networking и client-only код пиши по API конкретного loader'а и версии.
5. Не используй client-only классы в common/server-коде.
6. Не обновляй зависимости, Java или Minecraft-версию без явной необходимости задачи.
7. Не редактируй сгенерированные файлы, если можно изменить их источник или генератор.

## Сборка и проверки

В PowerShell используй Gradle wrapper:

```powershell
.\gradlew.bat buildAll -PmcVersion=1.20.1
.\gradlew.bat buildAll -PmcVersion=1.21.1
```

Для обычной проверки конкретного loader'а:

```powershell
.\gradlew.bat :fabric:build -PmcVersion=<version>
.\gradlew.bat :forge:build -PmcVersion=<version>
```

Перед финальным ответом укажи, какие команды проверки запускались и какие ограничения остались. Для изменений NeoForge не используй Forge-команды или зависимости как замену NeoForge-проверке.

## Git и стиль

- Не сбрасывай и не перезаписывай пользовательские изменения.
- Сохраняй существующий стиль Java и Gradle.
- Коммиты должны быть небольшими и тематическими, если пользователь отдельно попросит коммит.
- В комментариях и документации предпочитай ясные короткие формулировки на русском или английском в стиле существующего файла.
